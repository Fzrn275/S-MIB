- **Date:** 2026-05-20
- **Status:** Approved (design)

- **Prototype reference:** `.design-extracted/smib-app design/ScreensLearner.jsx` (screens 07–10), `App.jsx` (`PROJECTS`, `PROJECT_STEPS`, `BADGES_DATA`), `styles.css`

## 1. Goal & scope

Build the learner-facing project flow: four screens, a dual-mode (offline + Supabase) data layer,
the supporting SQL (`schema_day3.sql` + `seed.sql`), and pure-logic tests. Reuse the existing
domain models (`Project`/`GuidedProject`/`OpenProject`, `Step`, `Material`, `Progress`,
`Certificate`, `Student.addXp/bumpStreak`) — **no model rewrites**.

### In scope
- Screens: `LearnerHomeScreen`, `MyProjectsScreen`, `ProjectDetailScreen`, `StepDetailScreen`.
- Dual-mode data layer: repos for projects, progress, certificates, achievements; offline seed; local store.
- `progressService.completeStep` orchestration + `AuthContext.applyStepReward`.
- `schema_day3.sql` (projects, steps, progress, certificates, achievements catalog, user_achievements; `profiles.last_active_on`).
- `seed.sql` (12 projects, steps, 16-badge catalog) + offline JS seed.
- Navigation refactor: immersive learner native stack above the tabs.
- Reusable components ported from the prototype.
- Tests: a new `data` suite in `scripts/smoke.cjs`.

### Out of scope (deferred to later days)
AI Chat, Explore screen, Progress tab, Achievements/Certificate/Leaderboard screens, proof-photo
**upload** (the zone is a visual placeholder), badge **awarding** logic, video **playback**, creator
write paths, public certificate verification endpoint.

## 2. Architecture

```
Screens (src/screens/learner/*)
   │  read by id, refresh on focus
   ├─▶ repos/* (dual-mode)  ──▶ Supabase (when configured)  OR  data/seedData (offline)
   ├─▶ services/progressService.completeStep(...)  (orchestrates progress + cert side-effects)
   └─▶ AuthContext.applyStepReward({ xpDelta })     (owns XP/level/streak on the user)
```

- **Dual-mode strategy:** write-through, last-write-wins. Local AsyncStorage write is optimistic and
  authoritative for the UI; Supabase upsert is fired after. No offline queue, no conflict resolution.
- **Testability:** every repo + service accepts an injectable `deps = { store, db }` defaulting to the
  real AsyncStorage + the `supabase` singleton. Tests pass fakes so the data layer runs in the Node
  smoke runner.
- **Online learners start empty.** A freshly-registered Supabase learner has zero progress/badges and
  earns XP by doing steps. The prototype's populated "Level 4 / in-progress" look is reproduced only in
  **offline** mode via `seedData.js`.

## 3. `schema_day3.sql`

Columns map 1:1 to each model's `toRow()`/`fromRow()`. Identity PKs use `generated by default as
identity` so seed rows can pin ids 1–12 while later creator inserts auto-assign.

```sql
-- projects ────────────────────────────────────────────────────────────────
create table if not exists public.projects (
  id           bigint generated by default as identity primary key,
  title        text not null,
  category     text,
  difficulty   text default 'Easy'  check (difficulty in ('Easy','Medium','Hard')),
  duration     text,
  description  text,
  emoji        text default '🛠️',
  color        text default 'teal-img',
  creator_id   uuid references public.profiles (id) on delete set null,  -- null for seeded/system projects
  creator_name text,
  status       text not null default 'draft' check (status in ('draft','review','published','rejected')),
  enrolled     integer default 0,
  completion   integer default 0,
  rating       numeric default 0,
  cover_url    text,
  created_at   timestamptz default now(),
  type         text not null default 'guided' check (type in ('guided','open'))
);

-- steps ───────────────────────────────────────────────────────────────────
create table if not exists public.steps (
  project_id     bigint not null references public.projects (id) on delete cascade,
  step_n         integer not null check (step_n >= 1),
  title          text not null,
  instruction    text default '',
  tip            text,
  materials      jsonb default '[]'::jsonb,   -- array of {name,quantity,url,optional}
  xp             integer default 0,
  video_url      text,
  proof_required boolean default true,
  primary key (project_id, step_n)
);

-- progress ─────────────────────────────────────────────────────────────────
create table if not exists public.progress (
  id                     bigint generated by default as identity primary key,
  user_id                uuid not null references public.profiles (id) on delete cascade,
  project_id             bigint not null references public.projects (id) on delete cascade,
  completed_step_numbers integer[] default '{}',
  xp_earned              integer default 0,
  last_step_at           timestamptz,
  is_bookmarked          boolean default false,
  is_manually_completed  boolean default false,
  step_proofs            jsonb default '{}'::jsonb,  -- { [stepN]: {uri,uploadedAt} }
  step_ratings           jsonb default '{}'::jsonb,  -- { [stepN]: 1..5 }
  unique (user_id, project_id)
);

-- certificates ─────────────────────────────────────────────────────────────
create table if not exists public.certificates (
  id            bigint generated by default as identity primary key,
  code          text unique not null,
  project_id    bigint references public.projects (id) on delete set null,
  user_id       uuid not null references public.profiles (id) on delete cascade,
  project_title text,
  user_name     text,
  issued_at     timestamptz default now(),
  verify_url    text,
  unique (user_id, project_id)
);

-- achievements (catalog) ───────────────────────────────────────────────────
create table if not exists public.achievements (
  code        text primary key,
  tier        text not null check (tier in ('bronze','silver','gold','legendary')),
  icon        text,
  name        text not null,
  description text
);

-- user_achievements ────────────────────────────────────────────────────────
create table if not exists public.user_achievements (
  user_id          uuid not null references public.profiles (id) on delete cascade,
  achievement_code text not null references public.achievements (code) on delete cascade,
  earned_at        timestamptz default now(),
  primary key (user_id, achievement_code)
);

-- streak support on profiles ───────────────────────────────────────────────
alter table public.profiles add column if not exists last_active_on date;
```

### RLS

- `projects`, `steps`: enable RLS; **public read** where the project is `status='published'`
  (steps via an `exists` check on the parent project), plus owner read of own non-published rows.
- `progress`: owner CRUD — `using (user_id = auth.uid()) with check (user_id = auth.uid())`.
- `certificates`: owner select + insert. (Public verify-by-code deferred.)
- `achievements`: public read.
- `user_achievements`: owner select. (Insert policy deferred with badge awarding.)

Seeding runs in the Supabase SQL editor (service role) and bypasses RLS.

## 4. `seed.sql` + offline seed

### `supabase/seed.sql` — global shared data only
- **12 projects** (ids 1–12) from the prototype `PROJECTS`. Map `cat→category`, `diff→difficulty`,
  keep emoji/color/duration/desc/enrolled/completion/rating. `creator_id = null`,
  `creator_name` from the prototype. All `status='published'`, `type='guided'`.
- **Steps:** Project 1 = the 6 real prototype steps (full `materials` jsonb). Projects 2–12 = generated
  placeholder steps matching each project's step count (`title 'Step N: …'`, generic instruction,
  graduated xp e.g. `20 + 10*(n-1)`), so progress and % work for every project.
- **`achievements` catalog:** 16 rows from `BADGES_DATA` with stable codes (see §8).
- `select setval(pg_get_serial_sequence('public.projects','id'), 12, true);` so creator inserts don't collide.
- **Optional commented block** at the end: populate a demo learner's `progress` + earned
  `user_achievements` by looking up a profile by email (real auth uuid unknown at seed time).

### `src/data/seedData.js` — offline canonical data
Mirrors the same projects/steps/badge catalog as plain JS objects (row-shaped), **plus** demo
`progress` rows (matching the prototype's in-progress/done/% values) and the 6 earned badge codes.
Used by repos whenever `!isSupabaseConfigured()`, so the app demos fully offline.

**Offline = single demo learner.** Offline mode has exactly one local user, so the repos return the
seed demo progress/badges for whoever the current local learner is (not matched to a specific uuid).
Local writes are overlaid on top of the seed defaults (local wins), so completing a step offline
updates the populated demo and persists across launches.

## 5. Dual-mode data layer

New files and their contracts:

- `src/data/localStore.js` — namespaced AsyncStorage helpers. Keys: `smib.progress.<userId>`
  (object keyed by projectId), `smib.certs.<userId>` (array), `smib.lastActive.<userId>` (date string).
  `getJSON(key)`, `setJSON(key, value)`; accepts an injectable backing store.
- `src/repos/projectRepo.js`
  - `listProjects(opts?)` → `Project[]` (published).
  - `getProjectWithSteps(id)` → `Project` with `steps` hydrated.
  - Online: Supabase `projects` + `steps` queries → `Project.fromRow(row, stepRows)`. Offline: `seedData`.
- `src/repos/progressRepo.js`
  - `getAllProgress(userId)` → `Progress[]`. Online: remote rows, refreshing the local cache. Offline:
    seed demo progress overlaid by local-cache writes (local wins; see §4).
  - `getProgress(userId, projectId)` → `Progress | null`.
  - `saveProgress(progress)` → write-through: write `localStore` first, then Supabase
    `upsert(row, { onConflict: 'user_id,project_id' })` with null `id` stripped. Supabase failure is
    logged and swallowed (LWW). Returns the saved `Progress`.
- `src/repos/certificateRepo.js`
  - `listCertificates(userId)` → `Certificate[]`.
  - `issueCertificate(cert)` → idempotent on `(user_id, project_id)`: if one exists locally/remotely,
    return it; else write-through insert.
- `src/repos/achievementRepo.js`
  - `listCatalog()` → catalog rows (16). `listEarnedCodes(userId)` → `string[]`.
- `src/repos/index.js` — barrel.
- `src/services/progressService.js`
  - `completeStep({ user, project, progress, stepN, proofUri, rating, deps })`:
    1. `progress.completeStep(stepN, step.xp, { proofUri })`; if `rating`, `progress.rateStep(stepN, rating)`.
    2. `await progressRepo.saveProgress(progress)`.
    3. If `project.issuesCertificate() && project.isCompletedBy(progress)` → build `Certificate`
       (`Certificate.generateCode`) and `await certificateRepo.issueCertificate(cert)`.
    4. Return `{ xpDelta: step.xp, projectCompleted, certificate|null, newPct }`.

## 6. Step-completion side-effects

After `progressService.completeStep` resolves, `StepDetailScreen` calls
**`AuthContext.applyStepReward({ xpDelta })`**, which owns the user/profile:

1. Guard: learner only.
2. Clone the `Student` (`User.fromRow(user.toRow())`) so React re-renders, then `next.addXp(xpDelta)`
   (auto-levels via `LEVEL_THRESHOLDS`).
3. Streak: read `smib.lastActive.<userId>` / `profiles.last_active_on`. `today` → no-op;
   `yesterday` → `next.bumpStreak()`; older/none → `next.bumpStreak(true)` (reset to 1).
   Set last-active to today.
4. `setUser(next)` and persist write-through: AsyncStorage `LOCAL_USER_KEY` + (online)
   Supabase `profiles` update of `xp/level/streak/last_active_on`.

UI: the XP-burst overlay shows `+{xp} XP`, "Step Complete!", and "n of N steps done".

## 7. Screens, navigation, components

### Navigation refactor
ProjectDetail/StepDetail are immersive (no tab bar). Wrap the learner area in a native stack **above**
the tabs:

```
RoleRouter(learner) → LearnerStack (createNativeStackNavigator, headerShown:false)
   ├─ Tabs           (= LearnerTabs: Home[real] · Explore/Progress/Profile[placeholder])
   ├─ MyProjects     (params: none)
   ├─ ProjectDetail  (params: { projectId })

```
- New file `src/navigation/LearnerStack.js`; `RootNavigator.RoleRouter` renders it for learners.
- `LearnerTabs.js`: Home tab → `LearnerHomeScreen` (others stay `PlaceholderScreen`).
- Screens load by id from repos; `useFocusEffect` re-reads on return so progress/XP reflect updates.
- Params carry **ids only** (avoid stale objects).

### Screens (`src/screens/learner/`)
- `LearnerHomeScreen` — `LevelHeader` (greeting, streak, level badge, XP bar); 3 glass stat cards
  (Active/Done/Badges, tappable → MyProjects/Achievements-later); horizontal rails: Continue Learning

## 11. Resolved decisions
- Dual-mode = write-through, last-write-wins (no queue).
- Step completion side-effects: add XP + recompute level, bump daily streak, issue certificate on full
  GuidedProject completion. Badge **awarding** deferred (counts read from seeded `user_achievements`).
- `projects.id` = `bigint generated by default as identity`, seeded 1–12.
- Seed steps: Project 1 full (6 real steps); projects 2–12 generated placeholders.
- Online learners start empty; offline mode is the populated demo.
- `profiles.last_active_on` added for streak correctness.
